# 网页邮箱注册与内置扫码

版本：2026.10.31.2（2026-11-01 上线）

## 用户流程

1. 打开 https://app.leftseinem.dpdns.org/connect/，选择“邮箱注册”。
2. 填写自己的邮箱、至少 12 位密码，发送验证码；填入邮件中的 6 位验证码完成注册，再登录。
3. 电脑打开 Mydex → 配对手机 → 网页版配对，生成二维码。
4. 手机上在 Mydex 网页点击“扫描电脑配对码”，允许摄像头，扫描电脑二维码。
5. 核对电脑名称及两端 6 位确认码，确认绑定。电脑在线后打开会话。

摄像头不支持或被拒绝时，可选择“从相册读取二维码”，或粘贴电脑端配对链接。微信等内置浏览器若不允许摄像头，引导用户用系统浏览器打开同一网页，不假定浏览器自带扫码菜单。相册图片在浏览器本地解码，不上传服务器。

## 上线前必须完成的邮件配置

现已配置服务器私有 QQ SMTP 发信凭据。注册接口在未配置邮件时返回 503，不生成账号，不返回验证码，也不假装发送成功。

开通由项目所有者控制的邮箱/邮件投递服务；创建仅服务器可读的文件，例如：
`/path/to/deployment/projects/mydex-relay/private/smtp.json`

```json
{
  "host": "smtp.example.com",
  "port": 465,
  "user": "registration@example.com",
  "password": "SMTP授权码，不是网页登录密码",
  "from": "Mydex <registration@example.com>"
}
```

仅支持 TLS 465 或 STARTTLS 587；不关闭证书校验。不要将真实文件上传 GitHub。使用专用发件域名的服务时还需按服务商要求验证域名和配置 DNS。

真实投递及收件箱验证通过后，在现有服务器 config.json 增加：

```json
{
  "mailConfigFile": "/path/to/deployment/projects/mydex-relay/private/smtp.json",
  "requireVerifiedEmail": true
}
```

保留原 origin/dataFile/host/port。先备份 app 和账号库再部署；重启 Mydex-WebRelay 会使当前网页会话失效，用户需要重新登录，电脑会自动重连。不要重启正在执行任务的 Coding 工具。

`requireVerifiedEmail:true` 停用没有 emailVerifiedAt 的旧测试账号登录；不删除其历史绑定，不把测试账号的电脑自动分配给任何新注册账号。原使用者需验证自己的邮箱并重新在自己的电脑配对。

## 校验和限制

验证码有效期 10 分钟，每次只用一次，输错 5 次后失效；同邮箱 60 秒冷却、每小时最多 5 次，全站每小时最多 100 次。当前隧道下不信任任意客户端传来的 X-Forwarded-For，因此入口按连接来源有额外保守限流；扩大公测时再配置可信代理和独立限流存储。

验证码只在内存保存加盐摘要，服务器重启后需要重新发送；邮件账号凭据只读私有文件。登录切换会使当前浏览器之前的会话失效并关闭其实时通道；门户退出/401 清除该标签页电脑选择。不同浏览器账号不共享电脑授权。注册完成本身不能证明已解决用户反馈的具体串号根因；仍需用各自真实账号复查原问题。
