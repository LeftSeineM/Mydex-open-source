# 更新方式与统一更新源

适用版本：Android 0.2.4 / Windows 0.4.3。以下明确区分现有功能与后续设计。

**更新遇到问题？联系开发者：[348897402@qq.com](mailto:348897402@qq.com)**。请说明更新前后版本、系统版本、错误提示和复现步骤，不要附带配对令牌或 API Key。

## 现在如何更新

**手机应用内更新**：连接一台已配置更新包的电脑 → 设置 → 检查更新 → 确认下载 → Android 系统确认安装。客户端从当前连接的电脑读取 `/api/update`，下载 `/api/update/apk`，核对长度与 SHA-256，再交给系统安装。

如果电脑没有配置更新包，去 [GitHub Releases](https://github.com/LeftSeineM/Mydex-mobile/releases/latest) 下载 APK 并覆盖安装。自建连接器不会自动从项目作者的小主机获取新版。

**Windows 更新**：从 Releases 下载新安装包，先在托盘退出 Mydex，然后安装到原目录。私有 data 目录或导入的原配置保留。目前没有内置电脑自动更新器。

手机签名必须与旧版本一致，构建号必须递增。源代码自行构建的不同签名 APK 无法覆盖项目发布包。更新不会替你改变电脑中的模型供应商配置。

## 后续方案：小主机发布版本信号，客户端直接拉取

**这是设计说明，当前发布版尚未接入，也没有公开运营该更新服务。**

可以让常开小主机提供独立的公共更新站点：

```text
小主机更新站点 ── 版本清单 / 变更说明 / 安装包 ── 手机与 Windows 更新器

手机任务连接 ── 用户自己的电脑 A 或电脑 B
```

这里的“信号”是小体积版本清单。应用打开时或用户点击检查更新时读取清单，发现新版本后提示下载。下载直接从小主机完成；不依赖 Google Play 或第三方推送，也无需让用户的电脑转发任务。手机系统安装确认仍然保留，不能承诺静默安装或锁屏即时通知。

落地时需要完成：

1. 为更新站点提供稳定的 HTTPS 地址，与私人任务 API 分离。公共用户只访问发布文件，不接触任何电脑配对令牌。
2. 清单包含平台、版本、构建号、说明、文件大小和哈希，并使用独立发布密钥签名。仅靠哈希不等于清单来源可信；客户端需要验证签名与版本，拒绝意外降级。
3. 支持独立的更新源设置，支持关闭检查、自托管或回退手动下载。任务连接更换时不改变更新源；公共更新请求不带私人任务 Bearer Token。
4. 更新站点只服务固定发布文件，限制请求与下载并发。容量规划按实际包大小计算：约 50 MB 的 APK 下载 100 次约产生 5 GB 流量。
5. Android 新版先接入更新源；Windows 需要新增下载、验证、退出旧程序和替换文件的更新流程。目前 Windows 0.4.0 不具备这个流程。

统一更新源发布前，需要先推出包含该逻辑的客户端版本。现有 0.2.2 用户仍通过当前电脑更新入口或 Releases 完成这次过渡。

这项功能只承担软件分发，不把所有用户的项目、对话或工具账号汇集到小主机。
