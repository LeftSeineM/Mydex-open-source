# Mydex 发布检查清单

版本：1.0 · 2026-10-31

每次正式发布必须逐项核验，记录版本、文件大小、SHA-256、检查结果和截图路径。记录事实，不预先勾选。

## 1. 安装包

- 构建通过，版本号与包名一致，执行与改动相关的必要测试。
- Android 验证既有签名与 APK；Windows 验证安装包哈希和更新清单签名。
- 保留原始安装包与校验记录；已发布版本的二进制不能静默覆盖。

## 2. 所有发布入口一起同步

- 官网首页：版本文字、主下载按钮、页面内其他下载入口、适用的安装和配对说明。
- 官网下载目录：先放入并校验新版文件，再切换页面链接；保留旧版本供恢复。
- GitHub：公开 Release、下载文件、README 及相关手册。不得上传私有配置、令牌、签名私钥或私人对话截图。
- Android 软件内更新：检查本机、小主机以及当前实际使用的每个更新源；清单版本、versionCode、大小和哈希必须与 APK 一致。
- Windows 软件内更新：官网签名清单和 GitHub 备用清单同时同步，下载地址可用；已安装客户端能正确检查版本。
- 如需部署电脑端，保留原连接配置、令牌和证书，完成后检查服务恢复。不要用发布过程擅自重启无关 Coding 工具。
- 发布时检查实际部署位置和配置，不将历史地址当作永远有效；不新增对小主机的应用版连接依赖。

## 3. 从公网和软件入口验证

- 打开线上官网，而非仅检查本地 HTML；确认手机版和电脑版布局、版本文字及下载链接。
- 从首页实际链接完整下载新版安装包，核对大小和 SHA-256。仅 HTTP 200 或 HEAD 成功不算验证通过。
- 从实际软件更新接口读取清单，验证签名（适用时），获取对应包并核对哈希；等效入口指向同一已验证文件时可复用下载证据，避免重复消耗流量。
- 核对 GitHub Release 已公开、上传完成，资产哈希匹配。
- 保存页面截图和发布核验记录。区分自动化测试、桌面检查与手机真机实测；未做真机测试不得声称通过。

## 4. 收尾条件

官网首页、下载链接、GitHub 和软件内更新入口均同步并验证后，才告诉用户“发布完成”。有缺项时说明准确状态并继续处理；不能只完成其中一个入口便结束。

同步本地官网源和部署说明，避免下次部署旧页面或旧压缩包把版本退回。
