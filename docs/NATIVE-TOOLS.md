# 原会话接入 · 0.2.4 / 0.4.3

手机使用电脑端已经存在的会话。模型密钥、账号和权限仍由原工具保存，Mydex 不把一份聊天记录复制到另一套 Agent。

## 使用

1. 启动对应电脑上的 Coding 工具和 Mydex 连接器。
2. 在手机选择电脑，再从工具下拉框选择工具。没有项目时显示空项目区，已有会话仍出现在最近对话中。
3. 打开已有对话、继续发言；电脑原窗口和手机应显示同一条消息与回复。
4. 需要工具执行权限时，在原电脑客户端完成审批。手机不会自动批准。非 Codex 工具的模型和运行模式仍在原客户端设置。

网关通过现有 WSS 订阅发送更新，原会话快照约每 1.2 秒刷新。不同工具对生成中的部分文本暴露能力不同，不保证逐 token 同步；已完成回复和运行状态会同步。不要在请求超时后盲目重发，先检查原对话是否已收到。

## 已验证版本

| 工具 | 连接机制 | 使用条件 |
| --- | --- | --- |
| Kimi Code Desktop 1.2.0 | 桌面自带 REST 会话接口 | 桌面运行，本地服务令牌及日志可读 |
| DeepSeek Harness 0.2.1-rc.3 | 原 Desktop Host 的 session RPC | 安装本地兼容描述符补丁后重启 |
| ZCode 3.16.3 | 原 Host 的 TaskService | 安装本地兼容桥后重启；已实测 GLM-5.3 |
| Gemini CLI 0.66.0 | 原交互进程的提交回调与历史 | 安装本地交互桥；当前窗口需保持运行 |

Gemini 可续聊的是当前交互窗口已打开的会话。先在 Gemini 恢复要继续的历史，手机随后显示该会话；不会后台拉起另一进程接管正在运行的会话。关闭原程序后相应发送能力消失。本文不把 Gemini CLI 称为桌面 GUI。

Kimi 默认检查 `KIMI_CODE_HOME`、用户 `.kimi` 与本机便携配置目录，可通过连接器私有配置的 `local.kimiHome` 指定其他位置。仅连接日志声明的 loopback 服务，令牌不返回手机。

## 本地兼容安装（开发者）

厂商应用不是本仓库组成部分，安装包不包含修改后的厂商二进制。仅升级 APK 不会自动给电脑安装兼容补丁。

- `tools/prepare-tool-bridge.py` 为指定版本 ZCode / DeepSeek 生成补丁文件和完整原文件备份；先退出对应工具，再替换生成的 EXE 与 resources/app.asar。`--runtime` 指向固定安装目录中的 `desktop/bridges/zcode-session.cjs`，其旁边需有 `session-server.cjs`。`--descriptor` 放在当前用户 `.mydex/desktop-bridges/zcode.json` 或 `deepseek.json`。
- `tools/prepare-gemini-bridge.py --package <@google/gemini-cli目录> --backup <全新备份目录>` 修改受支持交互模块并保存原文件；运行时放在备份目录中，因此不要移动或删除该目录。
- 恢复时先退出对应工具，再恢复备份的原 EXE、ASAR 或 Gemini chunks。不要对厂商更新后的不同版本覆盖旧补丁或旧备份。
- ZCode / DeepSeek 的嵌入 ASAR 完整性摘要在存在时同步更新，未关闭完整性验证；修改后的二进制不再等同于原厂签名包。每次厂商版本变化都需要重新验证。

这次实测使用同一条会话中已保存的验证码，分别通过 Mydex 适配接口发送后收到 `KIMI-7391`、`DSH-7391`、`GLM-7391`、`GEMINI-7391`。测试覆盖原会话身份、基础文字与上下文；复杂工具调用、跨工具模型控制和所有图片附件格式不在本次验证范围内。
